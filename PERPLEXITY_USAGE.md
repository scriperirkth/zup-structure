# PERPLEXITY_USAGE.md — Регламент работы Perplexity с ЗУП 3.1

> Репозиторий: `scriperirkth/zup-structure`  
> Ветка: `main`  
> Главный источник структуры: `Configuration.xml`  
> Обязательные правила: `AI_RULES.md`

## 1. Порядок анализа

Для любого запроса по конфигурации соблюдать порядок:

1. Прочитать `AI_RULES.md`.
2. Проверить объект в `Configuration.xml`.
3. Определить тип объекта: `Document`, `Catalog`, `InformationRegister`, `CommonModule` и т. д.
4. Найти объект в соответствующей папке репозитория.
5. Прочитать XML объекта.
6. Проверить наличие `Ext/` и BSL-модулей.
7. Только после этого описывать реквизиты, формы, команды, движения, измерения или методы.
8. Если объект не найден — ответить `не найден в репозитории`.

Не использовать описание из типовой ЗУП как подтверждение наличия объекта в текущей выгрузке.

## 2. Источники истины

| Приоритет | Источник | Что подтверждает |
|---|---|---|
| 1 | `Configuration.xml` | Наличие объекта и его тип |
| 2 | XML объекта | Реквизиты, табличные части, свойства, состав |
| 3 | `Ext/*.bsl` | Код модуля объекта, менеджера, формы или сервиса |
| 4 | `CommonModules/` | Общая прикладная и интеграционная логика |
| 5 | `EventSubscriptions/` | Связь события и обработчика |
| 6 | `ScheduledJobs/` | Регламентный вызов экспортного метода |
| 7 | `README.md`, `TOP_OBJECTS_ZUP.md` | Навигация и примеры, не полный источник |

## 3. Поиск по имени

### Проверка существования объекта

```text
В репозитории scriperirkth/zup-structure, ветка main, проверь наличие объекта <Имя>.
Сначала найди его в Configuration.xml.
Верни: тип XML, путь к папке объекта, путь к XML объекта, наличие Ext и BSL-модулей.
Если объект не найден — напиши только «не найден в репозитории».
```

### Получение метаданных объекта

```text
Прочитай XML объекта <Тип>.<Имя> в репозитории scriperirkth/zup-structure, ветка main.
Перечисли только подтвержденные XML:
- реквизиты;
- табличные части и их реквизиты;
- измерения, ресурсы, реквизиты регистра;
- формы;
- команды;
- ссылки на другие объекты.
Не добавляй свойства, которых нет в XML.
```

### Поиск BSL-модуля

```text
Проверь BSL-модули объекта <Тип>.<Имя> в ветке main:
- Ext/ObjectModule.bsl;
- Ext/ManagerModule.bsl;
- Ext/RecordSetModule.bsl;
- Ext/Forms/*/Ext/FormModule.bsl.
Верни только реально найденные пути.
```

## 5. Поиск обработчиков

### Подписки на события

```text
Найди подписки на события для объекта <Тип>.<Имя>.
Проверь EventSubscriptions.
Для каждой подписки укажи:
- имя подписки;
- событие;
- источник;
- имя обработчика;
- общий модуль с обработчиком.
```

Не утверждать, что обработчик существует, пока не найден соответствующий BSL в `CommonModules/`.

### Регламентные задания

```text
Найди регламентные задания по ключевому слову <Слово>.
Для каждого задания укажи:
- имя;
- расписание и параметры из XML;
- вызываемый экспортный метод;
- модуль, где должен располагаться метод.
```

## 7. Обязательный формат ответа

```markdown
## <Тема>

**Статус:** найдено / не найдено  
**Подтверждение:** Configuration.xml / XML объекта / BSL-модуль

### Объекты

| Тип | Имя | Путь XML | BSL-модули |
|---|---|---|---|
| Document | <Имя> | `Documents/<Имя>/<Имя>.xml` | `Ext/ObjectModule.bsl` или «не проверено» |

### Подтверждённые свойства

- Реквизит: `<Имя>` — `<Тип>`
- Табличная часть: `<Имя>`
- Измерение регистра: `<Имя>`
- Ресурс регистра: `<Имя>`

### Ограничения

- <Что не удалось прочитать или подтвердить>
```

## 8. Маркеры достоверности

В ответах использовать один из статусов:

- `[подтверждено Configuration.xml]` — объект найден в составе конфигурации.
- `[подтверждено XML]` — свойства объекта прочитаны из его XML.
- `[подтверждено BSL]` — информация найдена в BSL-модуле.
- `[предположение по имени]` — назначение выведено только из имени.
- `[не найдено]` — объект, путь или модуль отсутствует либо не подтверждён.
- `[внешний источник]` — информация не из репозитория.

## 9. Запрещённые ответы

Нельзя:

- Придумывать объект, реквизит, табличную часть, регистр или общий модуль.
- Указывать путь, не найденный в репозитории.
- Называть BSL-модуль существующим без проверки `Ext/`.
- Подменять точное имя объекта похожим именем.
- Давать «список ключевых объектов», когда запрошены все.
- Утверждать бизнес-назначение, если оно не подтверждено XML или однозначным именем.
- Считать `README.md` полным списком метаданных.
- Использовать информацию из другой версии ЗУП без маркировки `[внешний источник]`.

## 10. Особенности GitHub

- Работа ведётся только в ветке `main`.
- Репозиторий используется в режиме чтения, пока пользователь явно не попросит изменить файл.
- Перед любым изменением файла показывать итоговый текст и запрашивать подтверждение.
- `Configuration.xml` имеет размер более 1 МБ и может не открываться через стандартный GitHub Contents API.
- Для крупных файлов использовать raw-содержимое, загрузку файла или приложенный пользователем файл.
- `ConfigDumpInfo.xml` является служебным файлом выгрузки и не служит источником прикладной логики.
