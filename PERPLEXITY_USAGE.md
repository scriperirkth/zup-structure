# PERPLEXITY_USAGE.md — Шаблоны запросов к репозиторию ЗУП КОРП 3.1

> Репозиторий: `scriperirkth/zup-structure`  
> Ветка: `main`  
> Правила достоверности, статусы, пути и формулировка «не найдено»: `AI_RULES.md` (главный документ).  
> Явный запрос пользователя важнее шаблонов этого файла.

## 1. Порядок анализа

1. Прочитать `AI_RULES.md` и `_ai/VERSION.md`.
2. Найти объект в реестре `_ai/objects/<Папка>.md` (если нужен весь состав или сверка с деревом, см. `_ai/objects.md`).
3. Определить тип объекта: `Document`, `Catalog`, `InformationRegister`, `CommonModule` и т. д.
4. Прочитать карточку `_ai/cards/<Папка>/<Имя>.md`; для критичных полей прочитать `<Папка>/<Имя>.xml`.
5. Методы модулей смотреть в `_ai/modules/<Папка>/<Имя>.md`, тело метода читать в `.bsl`.
6. Только после этого описывать реквизиты, формы, команды, движения, измерения или методы.
7. Если объект не найден, отвечать по AI_RULES.md, раздел 7.

Описание из типовой ЗУП не подтверждает наличие объекта в текущей выгрузке.

## 2. Поиск по имени

### Проверка существования объекта

```text
В репозитории scriperirkth/zup-structure, ветка main, проверь наличие объекта <Имя>.
Сначала найди его в реестре _ai/objects/<Папка>.md.
Верни: тип XML, путь к XML объекта, наличие каталога объекта, число файлов BSL, ссылку на карточку.
Если объект не найден, перечисли, что именно просмотрено.
```

### Получение метаданных объекта

```text
Прочитай карточку _ai/cards/<Папка>/<Имя>.md объекта <Тип>.<Имя> в репозитории scriperirkth/zup-structure, ветка main.
Перечисли только подтверждённое карточкой:
- реквизиты (тип, обязательность, связи выбора);
- табличные части и их реквизиты;
- измерения, ресурсы, реквизиты регистра;
- формы, команды, макеты;
- регистры движений.
Критичные поля подтверди по <Папка>/<Имя>.xml. Не добавляй свойства, которых нет в карточке и XML.
```

### Поиск методов модуля

```text
Найди методы объекта <Тип>.<Имя> в _ai/modules/<Папка>/<Имя>.md.
Верни: модуль, строку, вид, имя, параметры, признак Экспорт, директиву.
Тело метода читай в самом .bsl, а не по индексу.
Верни только реально найденные пути.
```

### Поиск BSL-модуля вручную

```text
Проверь BSL-модули объекта <Тип>.<Имя> в ветке main листингом каталогов:
- <Папка>/<Имя>/Ext/ObjectModule.bsl;
- <Папка>/<Имя>/Ext/ManagerModule.bsl;
- <Папка>/<Имя>/Ext/RecordSetModule.bsl (для регистров);
- <Папка>/<Имя>/Forms/<Форма>/Ext/Form/Module.bsl (модуль формы).
Верни только реально найденные пути.
```

## 4. Поиск обработчиков

### Подписки на события

```text
Найди подписки на события для объекта <Тип>.<Имя>.
Проверь EventSubscriptions.
Для каждой подписки укажи:
- имя подписки;
- событие;
- источник;
- имя обработчика;
- общий модуль с обработчиком.
```

Не утверждать, что обработчик существует, пока не найден соответствующий BSL в `CommonModules/` (индекс `_ai/modules/CommonModules/<Имя>.md` и тело метода в `.bsl`).

### Регламентные задания

```text
Найди регламентные задания по ключевому слову <Слово>.
Для каждого задания укажи:
- имя;
- расписание и параметры из XML;
- вызываемый экспортный метод;
- модуль, где должен располагаться метод.
```

## 6. Формат ответа

По умолчанию использовать OUTPUT_CONTRACT.md, если запрос пользователя не задаёт свой формат. Минимальная форма для простых справочных запросов:

```markdown
## <Тема>

Статус: найдено / не найдено в просмотренном  
Подтверждение: статусы из AI_RULES.md, раздел 6

### Объекты

| Тип | Имя | Путь XML | BSL-модули |
|---|---|---|---|
| Document | <Имя> | `Documents/<Имя>.xml` | `Documents/<Имя>/Ext/ObjectModule.bsl` или «не проверено» |

### Подтверждённые свойства

- Реквизит: `<Имя>` — `<Тип>` (ПОДТВЕРЖДЕНО XML)

### Ограничения

- <Что не удалось прочитать или подтвердить>
```

## 7. Запрещённые ответы

- Придумывать объект, реквизит, табличную часть, регистр или общий модуль.
- Указывать путь, не найденный в репозитории.
- Называть BSL-модуль существующим без листинга `Ext/` или индекса `_ai/modules`.
- Подменять точное имя объекта похожим.
- Давать «ключевые объекты», когда запрошен полный список.
- Утверждать бизнес-назначение без подтверждения XML или однозначным именем.
- Считать `README.md` полным списком метаданных.
- Считать индекс `_ai/modules` доказательством поведения: для статуса `ПОДТВЕРЖДЕНО BSL` нужно прочитанное тело метода.
- Использовать данные другой версии ЗУП без статуса `ВНЕШНИЙ ИСТОЧНИК`.

## 8. Особенности GitHub

- Работа ведётся в ветке `main`.
- Репозиторий используется в режиме чтения, пока пользователь явно не попросит изменить файл.
- Перед изменением файла показывать итоговый текст и запрашивать подтверждение.
- Ограничения чтения крупных файлов описаны в AI_RULES.md, раздел 11.
- `ConfigDumpInfo.xml` — служебный файл выгрузки, не источник прикладной логики.
- `_ai` — производный слой (AI_RULES.md, раздел 13): руками не править, обновляется скриптом `tools/build_ai_index.py`.
