# PERPLEXITY_USAGE.md — Работа с репозиторием ЗУП КОРП

> Репозиторий: `scriperirkth/zup-structure`
> Правила: `AI_RULES.md`.
> Актуальный снимок: `_ai/VERSION.md`.
> Этот документ задаёт шаблоны, а не заменяет текущий запрос пользователя.

## 1. Начало работы

1. Прочитать `AI_RULES.md` и `_ai/VERSION.md`.
2. Определить задачу, направление обмена при его наличии и целевые объекты.
3. Найти нужный реестр типа в `_ai/objects.md`.
4. Прочитать `_ai/objects/<Папка>.md` и все необходимые продолжения.
5. Перейти к карточке или исходному XML.
6. Найти методы по индексу и прочитать нужный BSL.

Сначала использовать материалы репозитория. Типовая документация и общие знания не подтверждают наличие конкретного объекта в данном снимке.

Если `_ai` отсутствует или не соответствует исходникам, продолжать по XML, BSL и дереву.

## 2. Источники и точность формулировок

- Реестр подтверждает зарегистрированный состав на снимок сборки.
- Карточка даёт производную сводку XML.
- Исходный XML подтверждает непосредственно прочитанную структуру.
- Индекс BSL показывает расположение метода, но не его алгоритм.
- Тело исходного BSL требуется для выводов о поведении.
- Тестовая база требуется для выводов об исполнении и данных.

Статусы использовать по `AI_RULES.md`, раздел 6.

Не говорить «прочитал XML», если получена только карточка.

`FillChecking=ShowError` не называть безусловной обязательностью во всех сценариях обмена.

## 3. Пути поиска

| Тип | Папка |
|---|---|
| Document | `Documents` |
| Catalog | `Catalogs` |
| InformationRegister | `InformationRegisters` |
| AccumulationRegister | `AccumulationRegisters` |
| CalculationRegister | `CalculationRegisters` |
| ChartOfCalculationTypes | `ChartsOfCalculationTypes` |
| ChartOfCharacteristicTypes | `ChartsOfCharacteristicTypes` |
| Enum | `Enums` |
| Constant | `Constants` |
| ExchangePlan | `ExchangePlans` |
| CommonModule | `CommonModules` |
| Report | `Reports` |
| DataProcessor | `DataProcessors` |
| PaletteColor | `PaletteColors` |

Остальные соответствия — `METADATA_MAP.md`.

Для объекта:

```text
_ai/objects/<Папка>.md
_ai/cards/<Папка>/<Имя>.md
<Папка>/<Имя>.xml
<Папка>/<Имя>/
_ai/modules/<Папка>/<Имя>.md
```

Для общего модуля:

```text
CommonModules/<Имя>.xml
CommonModules/<Имя>/Ext/Module.bsl
_ai/modules/CommonModules/<Имя>.md
```

Фактические пути форм и команд проверять по дереву, а не конструировать без проверки.

Ветка по умолчанию — `main`, если запрос не задаёт другую. При исследовании фиксировать конкретный коммит, когда это необходимо для воспроизводимости.

## 4. Шаблон проверки объекта

```text
Проверь объект <Тип>.<Имя> в scriperirkth/zup-structure.

Установи:
- зарегистрирован ли он в актуальном составе;
- где расположен исходный XML;
- есть ли карточка;
- какие BSL-файлы найдены;
- какой снимок исследован.

Отдельно различай регистрацию в составе и наличие файла в дереве.
Если поиск неполный, не утверждай отсутствие объекта.
```

## 5. Шаблон проверки структуры

```text
Исследуй структуру <Тип>.<Имя>.

Сначала прочитай карточку, если она есть.
Перечисли используемые задачей поля, их виды и типы.
Не смешивай реквизиты шапки, поля табличных частей, измерения и ресурсы.
Критичные сведения подтверди исходным XML.

Если исходный XML недоступен, обозначь сведения как полученные из карточки.
Отсутствие элемента в карточке не считай доказательством его отсутствия в XML.
```

## 6. Шаблон поиска логики

```text
Найди реализацию <Сценарий/Метод>.

Используй индекс BSL для навигации.
Прочитай тело релевантного метода и необходимые вызываемые методы.
Укажи:
- исходный файл;
- метод;
- контекст выполнения;
- условие вызова;
- используемые данные;
- эффект и обработку ошибок.

Сигнатура в индексе не подтверждает алгоритм.
Отсутствие записи в индексе не доказывает отсутствие метода.
```

## 7. Шаблон исследования обмена

```text
Исследуй обмен <Источник> -> <Приёмник> для значения <Значение>.

По фактическим правилам установи механизм обмена.
Проследи релевантную цепочку:
источник -> отбор -> выгрузка -> преобразование ->
сообщение -> загрузка -> поиск -> заполнение -> запись.

Проверяй метаданные обеих конфигураций и обработчики правил.
Не определяй механизм только по имени файла.
Не смешивай правила в репозитории с правилами, используемыми в базе.

Для исправления укажи точный файл, правило, обработчик и место выполнения.
Допущения отдели от подтверждённых фактов.
```

## 8. Тематический поиск

Искать по точным именам и релевантным фрагментам в реестрах типов.

Для полного списка проверить все относящиеся типы и части реестров.

Тематическая карта `TOP_OBJECTS_ZUP.md` — навигация. Её примеры после обновления релиза проверять заново.

По имени не делать выводов об алгоритме.

## 9. Обрезка и недоступные файлы

1. Зафиксировать, какой текст реально получен.
2. Проверить продолжения индексного файла.
3. Попробовать другой доступный способ чтения исходного текста.
4. По возможности сохранить тот же коммит.
5. Если необходимый фрагмент не получен, назвать ограничение и запросить минимальный текст.

Не повторять одинаковые неудачные вызовы и не выдавать поисковый фрагмент за полный метод.

Не обещать, что размер меньше 1 МБ гарантирует полное чтение коннектором.

## 10. Формат результата

Текущий запрос пользователя имеет приоритет.

Если иной формат не задан, достаточно:

- вывод по существу;
- подтверждённая основа с точными путями;
- изменение или код, если требуется реализация;
- допущения и ограничения;
- конкретный тест.

Развёрнутый формат из `OUTPUT_CONTRACT.md` применять по необходимости, без формального заполнения нерелевантных разделов.

По запросу полного кода давать полный изменяемый файл или метод, а не только вставку без контекста.

Не заявлять проверку в базе, выполнение кода или применение навыка без фактического выполнения.

## 11. Безопасность

Подготовка кода не разрешает запись в базу, запуск обмена и публикацию изменений.

GitHub используется в режиме чтения, пока пользователь не разрешит запись.

Перед внешней записью согласовать точный целевой файл и содержание по правилам используемых инструментов.

Не включать пароли, токены и персональные данные в ответы и логи.

## 12. Обновление производного слоя

Из корня локального репозитория:

```powershell
py tools\rebuild_ai.py --repo .
```

`build_ai_index.py` — используемая библиотека, не поддерживаемая точка запуска текущей полной сборки.

Сборку и перенос выгрузки не запускать без запроса пользователя. Не исправлять `_ai` вручную.

Коммит сборки в `_ai/VERSION.md` может отличаться от текущего HEAD, если позднее сохранены производные файлы или документация. Устаревание определять по изменениям исходников, а не только по различию SHA коммитов.
