# zup-structure

Выгрузка структуры метаданных конфигурации **1С:Зарплата и управление персоналом 3.1** в формате **EDT/XML**.

Репозиторий используется как справочник по именам и типам объектов метаданных для разработки, анализа структуры конфигурации, интеграций и навигации по XML-выгрузке.

## Назначение

Репозиторий предназначен для задач, где нужно:

- быстро найти точное имя объекта метаданных;
- понять, к какому XML-типу относится объект;
- перейти к нужной папке и XML-файлу объекта;
- использовать структуру конфигурации как справочник при разработке на 1С;
- анализировать состав конфигурации без открытия базы в конфигураторе.

## Ограничения

Важно учитывать следующие правила:

- Источником истины по составу объектов является `Configuration.xml`.
- Подробные свойства объекта подтверждаются только его XML-файлом.
- Назначение объекта по имени может использоваться только как навигационная подсказка.
- Если объект не найден в `Configuration.xml` или в соответствующей папке, его нельзя считать существующим в данной выгрузке.
- Репозиторий не должен использоваться как основание для предположений о типовой ЗУП вне фактически выгруженной структуры.

## Как искать объект

Рекомендуемый порядок поиска:

1. Найти объект в `Configuration.xml`.
2. Определить его XML-тип.
3. Перейти в соответствующую папку репозитория.
4. Прочитать XML объекта.
5. При необходимости проверить `Ext/` и связанные BSL-модули.

Примеры поисковых сценариев:

- найти документ по точному имени;
- найти все объекты по фрагменту имени, например `НДФЛ`, `Отпуск`, `СФР`, `Воин`;
- проверить, существует ли конкретный регистр;
- найти общий модуль или подписку на событие;
- установить фактический путь к объекту перед использованием в коде или документации.

## Использование в разработке

Репозиторий можно использовать как справочник для:

- подготовки запросов и обращений к метаданным;
- проверки точных русских имен объектов;
- навигации по выгрузке EDT/XML;
- составления карт объектов по предметным областям;
- анализа интеграционных точек, регистров, документов и общих модулей.

## Примеры синтаксиса 1С

Ниже приведены примеры **синтаксиса обращения**, а не доказательство наличия конкретного объекта в репозитории.

```bsl
// Документы
ДокОбъект = Документы.ДанныеДляРасчетаЗарплаты.СоздатьДокумент();

// Справочники
ЭлементСправочника = Справочники.Сотрудники.НайтиПоНаименованию("Иванов");

// Регистры сведений
НаборЗаписей = РегистрыСведений.НастройкиРасчетаЗарплаты.СоздатьНаборЗаписей();

// Планы видов расчета
ВидРасчета = ПланыВидовРасчета.Начисления.НайтиПоНаименованию("Оклад");

// Перечисления
ЗначениеПеречисления = Перечисления.<ИмяПеречисления>.<Значение>;
```

Если в примере требуется конкретный объект, его имя нужно предварительно подтвердить по `Configuration.xml`.

## Правила для AI и аналитики

При использовании репозитория как базы знаний необходимо соблюдать следующие принципы:

- не выдумывать объекты, которых нет в репозитории;
- не утверждать наличие реквизита без чтения XML;
- не утверждать наличие метода без проверки BSL;
- не относить объект к бизнес-разделу без достаточного подтверждения;
- при нехватке структуры явно сообщать об ограничении;
- использовать `AI_RULES.md` как нормативный документ для анализа.

## Рекомендуемый формат работы

Для автоматизированного анализа и ответов удобно использовать такой порядок:

1. Проверка объекта в `Configuration.xml`.
2. Определение XML-типа.
3. Поиск папки объекта.
4. Чтение XML объекта.
5. Поиск `Ext/*.bsl`, если требуется код.
6. Формирование ответа с указанием точных путей.

## Для чего НЕ предназначен репозиторий

Репозиторий не предназначен для:

- вывода о поведении прикладной логики без чтения BSL;
- подтверждения существования объектов в других версиях ЗУП;
- вывода о данных информационной базы;
- автоматического переноса знаний из типовой документации без сверки с XML.

## Примечание

Репозиторий следует рассматривать как **структурный справочник метаданных**.  
Все утверждения о составе конфигурации должны подтверждаться `Configuration.xml`, а все утверждения о свойствах конкретного объекта — его XML-файлом и, при необходимости, связанными BSL-модулями.
