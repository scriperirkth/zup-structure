# zup-structure

XML-метаданные и BSL-модули конфигурации «1С:Зарплата и управление персоналом КОРП», редакция 3.1.

Формат исходников — иерархическая выгрузка Конфигуратора.

Репозиторий предназначен для анализа структуры, разработки, исследования прикладной логики и обменов. Он не содержит фактические данные информационной базы.

## Версия и актуальность

Актуальные сведения о последней сборке производного слоя находятся в `_ai/VERSION.md`:

- имя и версия конфигурации;
- режим совместимости;
- версия формата XML;
- коммит исходного снимка;
- число объектов;
- число расхождений реестра с деревом;
- генератор и режим сборки.

Первичный источник свойств конфигурации — `Configuration.xml`.

Версия рабочей базы, номер установленной платформы и наличие расширений не подтверждаются одним репозиторием. Режим совместимости не равен номеру платформы, которой выполнена выгрузка.

## С чего начать

1. Прочитать `AI_RULES.md`.
2. Прочитать `_ai/VERSION.md`.
3. Найти нужный тип и объект в `_ai/objects.md` и `_ai/objects/`.
4. Прочитать карточку объекта, если она сформирована.
5. Для анализа поведения найти метод в индексе и прочитать исходный BSL.

Остальные документы читать по необходимости, не повторяя уже выполненную подготовку.

Явный запрос пользователя определяет задачу, порядок работы и формат ответа. При противоречии между документами репозитория главным является `AI_RULES.md`.

## Слой _ai

`_ai` — производный слой для навигации и чтения структуры без загрузки крупных исходных XML.

| Путь | Назначение |
|---|---|
| `_ai/VERSION.md` | Сведения о снимке и сборке |
| `_ai/objects.md` | Сводка состава и расхождения с деревом |
| `_ai/objects/<Папка>.md` | Реестр объектов конкретного типа |
| `_ai/cards/<Папка>/<Имя>.md` | Краткая карточка XML объекта |
| `_ai/modules/<Папка>/<Имя>.md` | Индекс методов BSL |
| `_ai/modules/_summary.md` | Сводка файлов BSL |

Карточки строятся не для всех типов. Отсутствие карточки не означает отсутствие объекта.

Таблицы и индексы могут продолжаться в файлах `.part2.md`, `.part3.md` и далее. Для полного поиска необходимо прочитать все относящиеся к нему части.

Карточка не является полным XML. Индекс методов не является анализом тела BSL.

`FillChecking=ShowError` в карточке отражает значение свойства XML. Оно не доказывает фактическое выполнение проверки в конкретном сценарии записи или обмена.

Вручную `_ai` не исправлять.

Навигационные примеры из Markdown необходимо заново сверять с актуальной выгрузкой, особенно после обновления релиза.

## Раскладка исходников

Описание объекта обычно расположено рядом с одноимённым каталогом:

```text
Documents/
├── ИмяДокумента.xml
└── ИмяДокумента/
    ├── Ext/
    │   ├── ObjectModule.bsl
    │   └── ManagerModule.bsl
    ├── Forms/
    │   ├── ИмяФормы.xml
    │   └── ИмяФормы/
    │       └── Ext/
    │           ├── Form.xml
    │           └── Form/
    │               └── Module.bsl
    └── Templates/
```

Это схема навигации, не требование наличия каждого файла. Проверять фактическое дерево конкретного объекта.

Общий модуль:

```text
CommonModules/ИмяМодуля.xml
CommonModules/ИмяМодуля/Ext/Module.bsl
```

Карта типов, включая `PaletteColor`, находится в `METADATA_MAP.md`.

## Инструменты

| Файл | Назначение |
|---|---|
| `tools/rebuild_ai.py` | Поддерживаемый запуск полной пересборки `_ai` |
| `tools/build_ai_index.py` | Базовая библиотека, используемая управляющим скриптом |
| `tools/find_orphans.py` | Вспомогательный отчёт по поддерживаемым типам объектов верхнего уровня |
| `tools/sync_dump.py` | Контролируемый перенос по заранее проверенному CSV |

Для актуальной полной сборки не запускать `build_ai_index.py` напрямую.

`find_orphans.py` не является универсальной проверкой выгрузки: его словарь типов может отставать, а вложенные формы и макеты он не проверяет. Отчёт не разрешает автоматическое удаление.

## Полная пересборка _ai на Windows

Из корня репозитория:

```powershell
py tools\rebuild_ai.py --repo .
```

Перед запуском зафиксировать изменения исходников, инструментов и документации. Допускаются изменения только внутри производного `_ai`.

Сборка выполняется в новую временную папку. После успешного завершения старый `_ai` сохраняется в соседний резервный каталог, а новый занимает его место.

При ошибке не публиковать частичный результат. Сохранить вывод и временные файлы для диагностики.

Размер частей индексов и таблиц по умолчанию — 24 КиБ. Карточки не делятся этим механизмом и могут быть крупнее.

## Порядок обновления большой конфигурации

1. Подготовить полную выгрузку нужной конфигурации в отдельную пустую папку.
2. Сверить имя, релиз, режим совместимости и формат XML.
3. Построить отчёт различий только для исходников конфигурации.
4. Проверить добавления, изменения и файлы только из прежнего дерева.
5. Перенести согласованный набор с резервным копированием.
6. Проверить результат и зафиксировать исходники отдельным коммитом.
7. Зафиксировать изменения генератора, если они нужны.
8. Выполнить полную пересборку `_ai`.
9. Проверить результат и зафиксировать `_ai` отдельным коммитом.
10. Согласовать документацию и только затем отправлять согласованное состояние в GitHub.

Не зеркалировать весь корень репозитория: `.git`, `_ai`, `tools`, документы и настройки Git не являются частью выгрузки конфигурации.

Обновление только документации после сборки не требует повторной генерации, если исходные XML, BSL и генератор не изменились.

## Ограничения

- XML подтверждает структуру, но не поведение отсутствующего BSL.
- Индекс подтверждает навигационные сведения, но не исполнение метода.
- Размер файла меньше лимита API не гарантирует отсутствие обрезки ответа коннектора.
- Репозиторий не подтверждает данные, права конкретного пользователя, производительность и результат исполнения.
- Подготовка кода не разрешает запуск обмена, запись в базы или публикацию изменений.
