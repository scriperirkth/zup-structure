# TASK_PATTERNS.md — Шаблоны задач для анализа ЗУП 3.1

> Репозиторий: `scriperirkth/zup-structure`  
> Ветка: `main`  
> Источник истины: `Configuration.xml`, XML объектов, реальные BSL-модули  
> Перед выполнением задачи обязательно читать `AI_RULES.md`.

## Базовый порядок

Для любой задачи:

1. Найти объект в `Configuration.xml`.
2. Подтвердить XML-тип объекта.
3. Найти фактическую папку объекта.
4. Прочитать XML объекта.
5. Проверить наличие `Ext/` и BSL-модулей.
6. Вернуть только подтверждённые сведения.
7. Если данных недостаточно — явно указать ограничение.

## 1. Проверка объекта

```text
Проверь объект <Тип>.<Имя> в репозитории scriperirkth/zup-structure, ветка main.

Нужно вернуть:
1. Найден ли объект в Configuration.xml.
2. XML-тип.
3. Путь к XML объекта.
4. Наличие Ext/.
5. Реальные пути к BSL-модулям.
6. Перечень подтвержденных свойств из XML.

Не предлагай аналоги, если объект не найден.
```

## 2. Анализ документа

```text
Проанализируй документ Документы.<Имя>.

Проверь:
- существование в Configuration.xml;
- свойства документа;
- реквизиты шапки;
- табличные части;
- реквизиты табличных частей;
- формы;
- команды;
- ObjectModule.bsl;
- ManagerModule.bsl;
- FormModule.bsl;
- связанные регистры и подписки на события.

Верни только сведения из XML и BSL.
```

## 3. Анализ справочника

```text
Проанализируй справочник Справочники.<Имя>.

Проверь:
- существование в Configuration.xml;
- иерархию;
- владельцев;
- реквизиты;
- табличные части;
- предопределенные данные;
- формы;
- ObjectModule.bsl;
- ManagerModule.bsl;
- FormModule.bsl;
- связанные регистры сведений.

Не делай выводы о назначении справочника без подтверждения XML.
```

## 4. Анализ регистра

```text
Проанализируй регистр <Тип>.<Имя>, где <Тип>:
- РегистрСведений;
- РегистрНакопления;
- РегистрРасчета.

Верни:
- точный XML-тип;
- периодичность;
- режим записи;
- измерения;
- ресурсы;
- реквизиты;
- регистраторы;
- подчиненные регистратору данные;
- формы;
- BSL-модули набора записей и менеджера.

Не называй поле измерением, ресурсом или реквизитом без XML-подтверждения.
```

## 5. Анализ начисления или удержания

```text
Найди объект <Имя> в плане видов расчета и связанных регистрах расчета.

Проверь:
- ChartsOfCalculationTypes;
- CalculationRegisters;
- связанные документы;
- зависимые показатели;
- BSL-обработчики;
- подписки на события;
- функциональные опции.

Верни фактические пути и только найденные связи.
```

## 7. Поиск обработчика события

```text
Найди все EventSubscriptions для объекта <Тип>.<Имя>.

Для каждой подписки верни:
- имя подписки;
- источник события;
- событие;
- имя обработчика;
- общий модуль;
- путь к BSL общего модуля.

Если обработчик в общем модуле не найден, так и укажи.
```

## 8. Поиск регламентного задания

```text
Найди регламентные задания по фрагменту «<Фрагмент>».

Для каждого задания верни:
- точное имя;
- путь к XML;
- расписание;
- вызываемый экспортный метод;
- общий модуль;
- путь к BSL общего модуля.

Не утверждай наличие экспортного метода до чтения BSL.
```

```text
подтвержденной XML или BSL.
```

## 10. Поиск использования объекта

```text
Найди, где используется <Тип>.<Имя>.

Проверить:
- XML-ссылки в объектах конфигурации;
- CommonModules;
- Documents;
- Catalogs;
- DataProcessors;
- Reports;
- EventSubscriptions;
- ScheduledJobs.

Раздели результат:
1. Прямые XML-ссылки.
2. Упоминания в BSL.
3. Подписки на события.
4. Регламентные задания.

Для каждого результата укажи файл и контекст использования.
```

## Запреты

- Не выдумывать объекты и пути.
- Не указывать реквизиты без XML.
- Не указывать методы без BSL.
- Не менять написание имён.
- Не считать `README.md` полным источником состава конфигурации.
- Не смешивать сведения из другой версии ЗУП без метки `[внешний источник]`.
