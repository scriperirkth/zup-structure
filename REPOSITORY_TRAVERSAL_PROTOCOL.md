# Протокол целевого обхода zup-structure

> Редакция: 2026-10-23. Применяется к выгрузке ЗУП, не к любому XML.

## Приоритет и подготовка

Текущий запрос → AI_RULES.md → этот протокол. Прочитать AI_RULES.md и _ai/VERSION.md, если ещё не получены для нужного снимка. Остальные документы — по необходимости. Определить цель, режим и границы.

## Источники

- Зарегистрированный состав: Configuration.xml или проверенный актуальный реестр _ai/objects.
- Свойства: исходный XML; карточка — производная неполная сводка.
- Файлы: фактическое дерево.
- Поведение: прочитанный исходный BSL; индекс — только навигация.
- Исполнение, данные и права: тестовая база или предоставленные результаты проверки.

## Порядок

1. Найти тип/объект в _ai/objects.md и реестре типа, учитывая продолжения.
2. Прочитать карточку, если есть.
3. Подтвердить существенные поля и типы необходимым исходным XML.
4. Найти нужный метод через индекс и прочитать тело с существенными зависимостями.
5. Исследовать только связанные с задачей формы, команды, макеты, подписки и вызовы.
6. Выдать результат с источниками, допущениями и проверкой.

Если _ai отсутствует или не соответствует исходникам, продолжать по XML, BSL и дереву. Configuration.xml не является обязательным первым чтением каждой задачи.

## Пути

Обычные ориентиры: <Папка>/<Имя>.xml и <Папка>/<Имя>/. Дополнительный каталог может отсутствовать. Для модулей объекта/менеджера — Ext/ObjectModule.bsl и Ext/ManagerModule.bsl; для общего модуля — CommonModules/<Имя>/Ext/Module.bsl. Формы, команды и макеты проверять по фактическому дереву; схема не доказывает наличие.

Не открывать все формы только потому, что они перечислены в XML. Полный аудит объекта выполнять только если он запрошен.

## Отрицательный вывод

Писать «не найдено в проверенном модуле/каталоге/снимке», указывая границы. Локальный вывод не требует обхода всех форм объекта. Общий вывод об отсутствии BSL во всём объекте требует проверки всех относящихся модулей и форм; при неполноте такой вывод не делать.

Отсутствие индекса или карточки не доказывает отсутствие элемента. Обрезка не равна отсутствию. По репозиторию не утверждать отсутствие в рабочей базе. Для полного списка читать все относящиеся части реестра.

## Режимы и изменение

ANALYZE — объяснение, DESIGN — проект, IMPLEMENT — код по запросу. Неполнота не запрещает независимую проектную реализацию. Предполагаемое подключение не называть подтверждённым.

Полный изменённый метод возвращать целиком; все новые/изменённые методы — полностью. Не переписывать неизвестные участки модуля. Указать точку вызова и сопутствующее. Не менять несвязанную логику.

## Несколько репозиториев

В обменах: ЗУП — настоящий протокол; structure_met — его README/UPDATE_GUIDE и опубликованная объектная навигация; pravila — его документы и выбранный комплект. Не применять пути ЗУП механически. Метаданные не подтверждают сопоставление, правила не подтверждают тип поля. Полная запись не равна полному бизнес-набору.

## Ограничения и безопасность

Получать полное нужное тело, не выдавать поисковый фрагмент за метод. При обрезке назвать пробел, попробовать другой реальный способ на том же снимке. Не повторять один блокер без новых действий, не требовать архив каждого объекта.

Подготовка кода не разрешает выполнение, генерацию, запись или публикацию. Проверки и скрипты — по отдельному запросу. Не обходить права и не добавлять опасные операции без требования.
