# AI_RULES.md — Правила работы ИИ с репозиторием scriperirkth/zup-structure

> Версия: 2.1  
> Дата: 2026-10-20  
> Основание: чтение корня репозитория, всех служебных документов и раскладки каталогов Documents/ИзменениеШтатногоРасписания и CommonModules/ОбщегоНазначения.

## 0. Приоритет и порядок чтения

- Явный запрос пользователя определяет порядок работы и формат ответа. Документы репозитория задают правила достоверности и формат по умолчанию.
- При противоречии между документами репозитория главным считается этот файл.
- Всегда читать: README.md и этот файл.
- По необходимости: PERPLEXITY_USAGE.md (шаблоны запросов), REPOSITORY_TRAVERSAL_PROTOCOL.md (обход объекта), OUTPUT_CONTRACT.md (формат ответа по умолчанию), METADATA_MAP.md (карта каталогов), TASK_PATTERNS.md, TOP_OBJECTS_ZUP.md.
- KNOWN_LIMITATIONS.md читать, когда вывод зависит от рабочей базы, прав, данных, версии или производительности.

## 1. Назначение репозитория

Репозиторий содержит XML-метаданные и BSL-модули конфигурации «1С:Зарплата и управление персоналом 3.1» (платформа 1С:Предприятие 8.3). Он используется как справочник имён и структуры объектов и как источник найденного BSL-кода для разработки, интеграций и обменов.

Формат: выгрузка Конфигуратора. Признаки: Configuration.xml, ConfigDumpInfo.xml, каталоги Ext/ и Forms/. В проверенных каталогах файлов формата .mdo (EDT) не встречено.

## 2. Раскладка объектов

Проверена 2026-10-20 на Documents/ИзменениеШтатногоРасписания и CommonModules/ОбщегоНазначения. Регистр букв в именах каталогов важен: Ext, Forms, Templates.

| Что | Путь |
|---|---|
| Описание объекта | `<Папка>/<Имя>.xml` (рядом с каталогом объекта, не внутри него) |
| Каталог объекта | `<Папка>/<Имя>/` |
| Модули объекта и менеджера | `<Папка>/<Имя>/Ext/ObjectModule.bsl`, `<Папка>/<Имя>/Ext/ManagerModule.bsl` |
| Общий модуль | `CommonModules/<Имя>/Ext/Module.bsl` |
| Описание формы | `<Папка>/<Имя>/Forms/<Форма>.xml` |
| Элементы формы | `<Папка>/<Имя>/Forms/<Форма>/Ext/Form.xml` |
| Каталог модуля формы | `<Папка>/<Имя>/Forms/<Форма>/Ext/Form/` (содержимое проверять листингом) |
| Макеты | `<Папка>/<Имя>/Templates/` |

Набор Ext/-файлов зависит от типа объекта. Наличие или отсутствие модуля подтверждается листингом конкретного каталога.

## 5. Запрет на выдумывание

- Нельзя называть объект существующим без подтверждения в Configuration.xml или в папке репозитория.
- Нельзя описывать реквизиты, измерения, ресурсы, табличные части без чтения XML объекта.
- Нельзя переименовывать объект или менять его тип.
- Нельзя относить объект к бизнес-разделу только по общим знаниям о ЗУП.
- Нельзя выдавать типовую документацию 1С за факт из репозитория.
- Объекты с префиксом «Удалить» реальны и учитываются с пометкой «к удалению».
- Если запрошен полный список, нельзя подменять его «ключевыми объектами».

## 6. Единые статусы

Этот набор статусов используют все документы репозитория.

| Статус | Значение |
|---|---|
| `ПОДТВЕРЖДЕНО СОСТАВОМ` | объект найден в Configuration.xml |
| `ПОДТВЕРЖДЕНО XML` | структура прочитана в XML |
| `ПОДТВЕРЖДЕНО BSL` | логика найдена в прочитанном BSL |
| `ПОДТВЕРЖДЕНО ДЕРЕВОМ` | файл или каталог найден в дереве репозитория |
| `ПРЕДПОЛОЖЕНИЕ ПО ИМЕНИ` | вывод сделан только из имени |
| `НЕ ПОДТВЕРЖДЕНО` | в просмотренных материалах данных для вывода нет |
| `ПРЕДЛОЖЕНИЕ ПРОЕКТА` | вариант решения, не факт о конфигурации |
| `ТРЕБУЕТ ПРОВЕРКИ В БАЗЕ` | зависит от рабочей базы, данных, прав, версии |
| `ВНЕШНИЙ ИСТОЧНИК` | сведения не из репозитория |

## 7. Формулировка «не найдено»

- Писать: «Не найдено в просмотренном: <список прочитанных файлов и каталогов>».
- Фразу «отсутствует в выгрузке» допустимо писать только после проверки Configuration.xml целиком (или готового реестра состава) и каталога типа.
- Выводы об отсутствии объекта в рабочей базе по репозиторию делать нельзя (см. KNOWN_LIMITATIONS.md).
- Если файл не удалось прочитать полностью (размер, обрезка), назвать это ограничением, а не считать объект отсутствующим.

## 8. Источники истины

| Приоритет | Источник | Что подтверждает |
|---|---|---|
| 1 | `Configuration.xml` | Состав объектов и их типы |
| 2 | `<Папка>/<Имя>.xml` | Реквизиты, измерения, ресурсы, табличные части, перечень форм |
| 3 | `.bsl` в `<Папка>/<Имя>/Ext/` и `Forms/` | Поведение |
| 4 | Имя папки или объекта | Тип объекта; тематика только как предположение |
| 5 | Типовая документация ЗУП 3.1 | Только со статусом `ВНЕШНИЙ ИСТОЧНИК` |

## 9. Порядок работы с объектом

1. Найти объект в Configuration.xml и подтвердить тип.
2. Определить путь `<Папка>/<Имя>.xml` и каталог `<Папка>/<Имя>/`.
3. Прочитать XML объекта.
4. Извлечь только то, что есть в файле.
5. Листингом проверить Ext/ и Forms/ и прочитать нужные BSL.
6. Классифицировать по бизнес-разделу: однозначное имя — раздел со статусом `ПРЕДПОЛОЖЕНИЕ ПО ИМЕНИ`; неоднозначное — «Технические и инфраструктурные объекты».

## 10. Правила ответа

- Указывать точный тип объекта и точный путь к файлу.
- Не смешивать объекты разных типов в одном утверждении.
- При запросе полного списка давать все объекты; количество должно совпадать с репозиторием.
- Если объект не найден, действовать по разделу 7, не предлагать аналоги без запроса.
- Формат ответа по умолчанию — OUTPUT_CONTRACT.md, если запрос пользователя не задаёт свой.

## 11. Ограничения GitHub API

- Файлы больше 1 МБ (Configuration.xml, ConfigDumpInfo.xml) ранее не открывались через Contents API; на дату 2026-10-20 это повторно не проверялось. Для них использовать raw-ссылку: https://raw.githubusercontent.com/scriperirkth/zup-structure/main/<файл>, загрузку файла или приложение от пользователя.
- Крупные файлы меньшего размера (например, CommonModules/ОбщегоНазначения/Ext/Module.bsl, 753 747 байт) могут обрезаться при чтении. Фрагмент не выдавать за полный файл.
- Листинг папки возвращает имена и типы, но не содержимое.

## 12. Версионирование правил

При изменении структуры репозитория этот файл обновляется первым. Расхождения между документами устраняются приведением остальных документов к этому файлу.
