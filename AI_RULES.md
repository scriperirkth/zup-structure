> Версия: 2.2  
> Дата: 2026-10-20  
> Основание: чтение корня репозитория, всех служебных документов, раскладки каталогов Documents/ИзменениеШтатногоРасписания и CommonModules/ОбщегоНазначения, слоя `_ai`.

## 0. Приоритет и порядок чтения

- Явный запрос пользователя определяет порядок работы и формат ответа. Документы репозитория задают правила достоверности и формат по умолчанию.
- При противоречии между документами репозитория главным считается этот файл.
- Всегда читать: README.md, этот файл и `_ai/VERSION.md`.
- Поиск объекта: `_ai/objects/<Папка>.md`, затем `_ai/cards/<Папка>/<Имя>.md`, затем XML объекта.
- Методы модулей: `_ai/modules/<Папка>/<Имя>.md`, затем нужный `.bsl`.
- По необходимости: PERPLEXITY_USAGE.md (шаблоны запросов), REPOSITORY_TRAVERSAL_PROTOCOL.md (обход объекта), OUTPUT_CONTRACT.md (формат ответа по умолчанию), METADATA_MAP.md (карта каталогов), TASK_PATTERNS.md, TOP_OBJECTS_ZUP.md.
- KNOWN_LIMITATIONS.md читать, когда вывод зависит от рабочей базы, прав, данных, версии или производительности.

## 1. Назначение репозитория

Репозиторий содержит XML-метаданные и BSL-модули конфигурации «1С:ЗУП КОРП», редакция 3.1 (по `Configuration.xml`: `ЗарплатаИУправлениеПерсоналомКОРП`, версия 3.1.38.69, режим совместимости Version8_3_27; платформа 1С:Предприятие 8.3). Он используется как справочник имён и структуры объектов и как источник найденного BSL-кода для разработки, интеграций и обменов.

Формат: выгрузка Конфигуратора (version 2.21). Признаки: Configuration.xml, ConfigDumpInfo.xml, каталоги Ext/ и Forms/. В проверенных каталогах файлов формата .mdo (EDT) не встречено.

Версия рабочей базы по репозиторию не подтверждается (см. KNOWN_LIMITATIONS.md).

## 5. Запрет на выдумывание

- Нельзя называть объект существующим без подтверждения в реестре `_ai/objects/<Папка>.md`, Configuration.xml или в папке репозитория.
- Нельзя описывать реквизиты, измерения, ресурсы, табличные части без чтения карточки или XML объекта.
- Нельзя переименовывать объект или менять его тип.
- Нельзя относить объект к бизнес-разделу только по общим знаниям о ЗУП.
- Нельзя выдавать типовую документацию 1С за факт из репозитория.
- Объекты с префиксом «Удалить» реальны и учитываются с пометкой «к удалению».
- Если запрошен полный список, нельзя подменять его «ключевыми объектами».

## 6. Единые статусы

Этот набор статусов используют все документы репозитория.

| Статус | Значение |
|---|---|
| `ПОДТВЕРЖДЕНО СОСТАВОМ` | объект найден в Configuration.xml или в реестре `_ai/objects` |
| `ПОДТВЕРЖДЕНО XML` | структура прочитана в XML или в карточке `_ai/cards` |
| `ПОДТВЕРЖДЕНО BSL` | логика найдена в прочитанном теле метода BSL |
| `ПОДТВЕРЖДЕНО ДЕРЕВОМ` | файл или каталог найден в дереве репозитория |
| `ПРЕДПОЛОЖЕНИЕ ПО ИМЕНИ` | вывод сделан только из имени |
| `НЕ ПОДТВЕРЖДЕНО` | в просмотренных материалах данных для вывода нет |
| `ПРЕДЛОЖЕНИЕ ПРОЕКТА` | вариант решения, не факт о конфигурации |
| `ТРЕБУЕТ ПРОВЕРКИ В БАЗЕ` | зависит от рабочей базы, данных, прав, версии |
| `ВНЕШНИЙ ИСТОЧНИК` | сведения не из репозитория |

## 7. Формулировка «не найдено»

- Писать: «Не найдено в просмотренном: <список прочитанных файлов и каталогов>».
- Фразу «отсутствует в выгрузке» допустимо писать только после проверки реестра `_ai/objects/<Папка>.md` (построен из Configuration.xml) и каталога типа.
- Файл в дереве, отсутствующий в Configuration.xml (см. `_ai/objects.md`, раздел «Расхождения»), не считается частью конфигурации: статус `ПОДТВЕРЖДЕНО ДЕРЕВОМ`, не `ПОДТВЕРЖДЕНО СОСТАВОМ`.
- Выводы об отсутствии объекта в рабочей базе по репозиторию делать нельзя (см. KNOWN_LIMITATIONS.md).
- Если файл не удалось прочитать полностью (размер, обрезка), назвать это ограничением, а не считать объект отсутствующим.

## 9. Порядок работы с объектом

1. Найти объект в `_ai/objects/<Папка>.md` и подтвердить тип.
2. Прочитать карточку `_ai/cards/<Папка>/<Имя>.md`.
3. Для критичных полей (типы, обязательность, связи выбора) подтвердить по `<Папка>/<Имя>.xml`.
4. Найти методы в `_ai/modules/<Папка>/<Имя>.md` и прочитать тело нужного метода в `.bsl`.
5. Извлекать только то, что есть в файлах.
6. Классифицировать по бизнес-разделу: однозначное имя — раздел со статусом `ПРЕДПОЛОЖЕНИЕ ПО ИМЕНИ`; неоднозначное — «Технические и инфраструктурные объекты».

## 10. Правила ответа

- Указывать точный тип объекта и точный путь к файлу.
- Не смешивать объекты разных типов в одном утверждении.
- При запросе полного списка давать все объекты; количество должно совпадать с репозиторием.
- Если объект не найден, действовать по разделу 7, не предлагать аналоги без запроса.
- Формат ответа по умолчанию — OUTPUT_CONTRACT.md, если запрос пользователя не задаёт свой.

## 11. Ограничения GitHub API

- `Configuration.xml` (1 112 372 байт) не открывается через Contents API: проверено 2026-10-20, ошибка про размер больше 1 МБ. Состав брать из `_ai/objects.md`. `ConfigDumpInfo.xml` не использовать как источник логики.
- Крупные файлы меньшего размера (например, CommonModules/ОбщегоНазначения/Ext/Module.bsl, 753 747 байт) могут обрезаться при чтении. Фрагмент не выдавать за полный файл.
- Файлы `_ai` не превышают 716 802 байт (проверено 2026-10-20) и читаются целиком. Крупные индексы модулей разбиты на части `*.part2.md`, `*.part3.md`.
- Листинг папки возвращает имена и типы, но не содержимое.

## 12. Версионирование правил

При изменении структуры репозитория этот файл обновляется первым. Расхождения между документами устраняются приведением остальных документов к этому файлу.

## 13. Слой _ai

`_ai` — производный слой, построенный скриптом `tools/build_ai_index.py` из Configuration.xml, XML объектов и BSL. Руками не править.

- Реестр (`_ai/objects.md`, `_ai/objects/<Папка>.md`) подтверждает состав на коммит из `_ai/VERSION.md`.
- Карточка (`_ai/cards/...`) подтверждает структуру как `ПОДТВЕРЖДЕНО XML` на коммит из её заголовка. Для решений об изменении кода и правил критичные поля подтверждать по исходному XML.
- Индекс модулей (`_ai/modules/...`) показывает расположение методов. Статус `ПОДТВЕРЖДЕНО BSL` ставится только после чтения тела метода. Индекс построен по шаблону заголовков `Процедура`/`Функция` и мог пропустить нестандартно оформленный метод.
- Если коммит в заголовке карточки или индекса отличается от коммита в `_ai/VERSION.md`, объект мог измениться: сверить с исходным XML или BSL.
- `_ai/VERSION.md` не подтверждает версию рабочей базы.
