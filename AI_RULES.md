# AI_RULES.md — Правила работы с scriperirkth/zup-structure

> Версия документа: 2.3
> Дата: 2026-10-22
> Формат исходников: выгрузка Конфигуратора, XML и BSL.
> Актуальные сведения о снимке: `_ai/VERSION.md` и `Configuration.xml`.

## 0. Приоритет и подготовка

- Явный запрос пользователя определяет задачу, порядок работы и формат ответа.
- При противоречии между документами репозитория главным считается этот файл.
- Сначала прочитать этот файл и `_ai/VERSION.md`.
- README использовать как карту репозитория.
- Остальные документы читать по необходимости.
- Не перечитывать полученные материалы без причины.
- Не превращать служебные расхождения в автоматический запрет на исследование.
- Документы репозитория не отменяют требования безопасности используемой среды.

Если `_ai` отсутствует или устарел, продолжать по исходным XML, BSL и фактическому дереву.

## 1. Назначение и версия

Репозиторий содержит структуру и код конфигурации «1С:Зарплата и управление персоналом КОРП», редакция 3.1.

Не фиксировать текущий релиз, число объектов и размеры исходников в правилах как неизменные значения. Для конкретной задачи читать актуальные данные из `_ai/VERSION.md` и при необходимости `Configuration.xml`.

Различать:

- версию конфигурации;
- версию формата XML;
- режим совместимости;
- номер платформы;
- версию рабочей базы.

Режим совместимости не доказывает номер установленной платформы. Репозиторий не доказывает совпадение с рабочей базой.

## 2. Раскладка объектов

| Что | Путь для навигации |
|---|---|
| XML объекта | `<Папка>/<Имя>.xml` |
| Каталог объекта | `<Папка>/<Имя>/` |
| Модуль объекта | `<Папка>/<Имя>/Ext/ObjectModule.bsl` |
| Модуль менеджера | `<Папка>/<Имя>/Ext/ManagerModule.bsl` |
| Общий модуль | `CommonModules/<Имя>/Ext/Module.bsl` |
| Описание формы | `<Папка>/<Имя>/Forms/<Форма>.xml` |
| Состав формы | `<Папка>/<Имя>/Forms/<Форма>/Ext/Form.xml` |
| Модуль формы | `<Папка>/<Имя>/Forms/<Форма>/Ext/Form/Module.bsl` |
| Макеты | `<Папка>/<Имя>/Templates/` |

Это распространённая схема, а не доказательство существования файла. Для общих форм, команд, регистров и других типов фактическая раскладка может отличаться.

Регистр букв в путях сохранять. Наличие и отсутствие файлов проверять по дереву.

## 3. Карта типов

Соответствия XML-типов и каталогов находятся в `METADATA_MAP.md`.

Актуальный состав — в `Configuration.xml` и производном реестре `_ai/objects`.

Не утверждать наличие модуля только по типу метаданных.

`PaletteColor` соответствует каталогу `PaletteColors`.

Неизвестный тип не сопоставлять с каталогом молча. Проверить фактические файлы и описание типа.

Markdown-документы и имена объектов не заменяют первичные источники.

## 5. Запрет на выдумывание

- Не придумывать объекты, поля, методы и переменные контекста обработчика.
- Не описывать свойства без прочитанного источника.
- Не менять точное имя объекта на похожее.
- Не переносить сведения другой конфигурации или релиза без явной маркировки.
- Не выдавать назначение по имени за установленный алгоритм.
- Не игнорировать элементы с префиксом «Удалить»: их наличие и использование проверяются отдельно.
- Если запрошен полный список, не заменять его подборкой примеров.
- Не заявлять чтение файла, применение навыка или проверку кода без выполнения соответствующего действия.

## 6. Статусы доказательств

| Статус | Значение |
|---|---|
| `ПОДТВЕРЖДЕНО СОСТАВОМ` | Объект найден в Configuration.xml либо в проверенном актуальном производном реестре |
| `ПОДТВЕРЖДЕНО XML` | Сведения прочитаны непосредственно в исходном XML |
| `ПОДТВЕРЖДЕНО КАРТОЧКОЙ` | Сведения получены из производной карточки; исходный XML непосредственно не прочитан |
| `ПОДТВЕРЖДЕНО BSL` | Нужный фрагмент исходного BSL прочитан |
| `ПОДТВЕРЖДЕНО ИНДЕКСОМ` | Найдена навигационная запись о файле или методе |
| `ПОДТВЕРЖДЕНО ДЕРЕВОМ` | Файл или каталог найден в дереве |
| `ПРЕДПОЛОЖЕНИЕ ПО ИМЕНИ` | Вывод основан только на имени |
| `НЕ ПОДТВЕРЖДЕНО` | Данных недостаточно |
| `ПРЕДЛОЖЕНИЕ ПРОЕКТА` | Предлагаемая реализация, не установленный факт о конфигурации |
| `ТРЕБУЕТ ПРОВЕРКИ В БАЗЕ` | Зависит от среды, данных, прав или фактического исполнения |
| `ВНЕШНИЙ ИСТОЧНИК` | Сведения получены вне репозитория |

Пометки внутри сгенерированного текста не повышают уровень доказательств автоматически. Если ИИ прочитал только карточку, не утверждать, что он прочитал исходный XML.

Статусы нужны для существенных выводов. Не перегружать ими каждую строку, если источник и границы уже указаны.

## 7. Отсутствие и неполный поиск

- Писать «не найдено в просмотренных материалах», перечисляя существенные границы поиска.
- Не смешивать отсутствие регистрации объекта и отсутствие файла.
- Если файл есть, а регистрации нет, отдельно указать оба обстоятельства.
- Вывод «не зарегистрирован в составе этой выгрузки» требует проверки полного актуального реестра соответствующего типа.
- При делении таблицы на части проверить все части.
- Отсутствие записи в индексе не доказывает отсутствие метода.
- Отсутствие карточки не доказывает отсутствие объекта.
- Обрезанный или недоступный файл не считается отсутствующим.
- По репозиторию не утверждать отсутствие объекта или кода в рабочей базе.

Фраза «отсутствует в выгрузке» без уточнения регистрации и дерева нежелательна.

## 8. Первичные и производные данные

При расхождении первичный XML или BSL имеет приоритет над карточкой и индексом.

Прежде чем использовать производные данные:

1. Установить коммит сборки по `_ai/VERSION.md`.
2. Проверить коммит в нужном производном файле.
3. При наличии более новых изменений исходника сверить его непосредственно.
4. При необходимости проверить SHA-256, указанный в карточке или индексе.

Различие HEAD и коммита сборки само по себе не доказывает устаревание: последующие коммиты могут содержать только `_ai` или документацию.

Совпадение номера релиза само по себе не гарантирует идентичность исходников.

## 9. Порядок исследования

1. Определить целевой объект и границы задачи.
2. Найти объект в реестре `_ai/objects`.
3. Прочитать карточку, если она есть.
4. Для существенных решений подтвердить используемые поля и типы по исходному XML.
5. Найти нужные методы по индексу.
6. Прочитать тело метода и релевантные вызовы в BSL.
7. Просмотреть только необходимые формы, команды, макеты и зависимости.
8. Отделить подтверждённые факты от проектных решений и проверок в базе.

Не выполнять полный обход нерелевантных модулей и форм ради формального manifest.

Для задач обмена дополнительно проверять источник, приёмник, механизм, обработчики, поиск, заполнение и запись в пределах исследуемого значения.

## 10. Режим и результат

Если запрос пользователя задаёт режимы или формат, использовать их.

По умолчанию:

- `ANALYZE` — исследование;
- `DESIGN` — проектирование;
- `IMPLEMENT` — подготовка реализации.

Прямое требование исправить или написать код означает подготовку реализации, но не разрешает исполнение или публикацию.

Неподтверждённая зависимость ограничивает использующий её участок, а не автоматически всё решение.

Неопределённость, меняющая идентификацию или сохранность данных, требует конкретного уточнения. Независимую часть результата выдавать сразу.

Указывать точные файлы, элементы и точки изменения. Не подменять код универсальным отчётом или заглушками.

При генерации BSL соблюдать требования пользователя и фактически доступные навыки оформления.

## 11. Чтение через инструменты

GitHub Connector — основной способ доступа, если он доступен.

- Листинг не равен чтению содержимого.
- Размер ниже лимита API не гарантирует полного ответа коннектора.
- Поисковый фрагмент не равен полному методу.
- Индексы и таблицы могут иметь продолжения `.part2.md`, `.part3.md` и далее.
- Важный вывод об отсутствии требует проверки всех релевантных частей.
- При обрезке попробовать другой доступный способ чтения того же исходника.
- По возможности сохранять тот же коммит; переход на другую версию обозначать.
- Не повторять одинаковые неработающие вызовы.
- При недоступном фрагменте назвать ограничение и запросить минимальный необходимый текст один раз.

Не выдавать получение файла через инструмент за проверку его выполнения.

## 13. Генерация и обновление _ai

Поддерживаемый запуск из корня:

```powershell
py tools\rebuild_ai.py --repo .
```

`tools/build_ai_index.py` используется как библиотека. Прямой запуск старого генератора не является актуальной процедурой обновления.

Полная сборка выполняется в новую папку. После успешного завершения старый `_ai` сохраняется вне репозитория, новый публикуется на его месте.

По умолчанию индексные части ограничены 24 КиБ. Карточки могут быть больше. Это не гарантия чтения любого файла без обрезки.

Карточки являются неполными сводками XML.

`FillChecking=ShowError` отражает настройку XML, а не безусловную обязательность поля при любой записи или загрузке. Фактический сценарий проверяется по BSL и в базе.

Индекс методов построен эвристически. Он может пропустить нестандартный заголовок или неверно распознать конструкцию. Для анализа поведения читать исходник.

Номера строк и хеши относятся к снимку сборки.

Слой `_ai` вручную не править. После изменения исходников или генератора выполнить новую полную сборку. Изменение только документации пересборки не требует.

`find_orphans.py` — вспомогательный отчёт с ограниченным словарём типов, не универсальное основание для удаления.

Перенос новой выгрузки выполняется отдельно от генерации: с проверкой различий, резервным копированием и контролем результата.
